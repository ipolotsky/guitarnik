# Гитарник - Кэмп U

Сайт для сбора песен на вечер живой музыки. Гости без регистрации смотрят список, лайкают, добавляют свои песни и заказывают чужие. Организаторы собирают лайнап и заходят в админку по паролю.

Стек: Node.js, Express, EJS, Bootstrap 5.3 с CDN, PostgreSQL, Google Sheets через сервис-аккаунт.

## Где лежат данные

Основное хранилище - PostgreSQL. Адрес базы в переменной `DATABASE_URL`, схема создается сама при старте.

Google-таблица подключается отдельно и работает как зеркало. Когда она подключена, каждая новая или измененная строка уходит в нее в фоне, а если таблица недоступна, запись ждет в очереди и уедет позже. В админке на сводке есть две кнопки: «Выгрузить все в таблицу» переписывает листы содержимым базы, «Загрузить из таблицы» затягивает строки обратно в базу по id. Загрузка ничего не удаляет: строка, стертая в таблице руками, останется в базе, пока ее не отменят через админку.

Сайт полностью работает и без всякой таблицы, подключить ее можно когда угодно.

## Бекапы

Бекапами занимается databasus, он поднимается рядом отдельным контейнером и слушает порт 4005 только на локальном интерфейсе сервера. Наружу он не смотрит, поэтому открывать его нужно через туннель:

```
ssh -L 4005:127.0.0.1:4005 demo-mountly
```

Дальше открыть `http://localhost:4005` и настроить расписание. Параметры подключения к базе: хост `postgres`, порт `5432`, база `guitarnik`, пользователь `guitarnik`, пароль из `POSTGRES_PASSWORD` в `~/guitarnik/.env`.

Выгрузка `/admin/export/data.json` отдает все три таблицы одним файлом, это быстрый способ забрать данные руками.

## Настройка Google

1. Создать проект в Google Cloud Console.
2. Включить в нем Google Sheets API.
3. Создать сервис-аккаунт и ключ к нему в формате JSON, скачать файл ключа.
4. Создать Google-таблицу и расшарить ее на email сервис-аккаунта с правом редактирования. Email виден в поле `client_email` в файле ключа.
5. Скопировать `SPREADSHEET_ID` из адреса таблицы: это длинный кусок между `/d/` и `/edit`.
6. Превратить ключ в одну строку base64:

```
base64 -i key.json | tr -d '\n' | pbcopy
```

Полученную строку положить в `GOOGLE_SERVICE_ACCOUNT_JSON`, id таблицы в `SPREADSHEET_ID`, перезапустить сайт. Файл ключа в репозиторий не класть.

Дальше в админке открыть «Настройки таблицы», нажать «Создать структуру», потом на сводке «Выгрузить все в таблицу».

## Переменные окружения

`PORT`, `ADMIN_PASSWORD`, `SESSION_SECRET`, `DATABASE_URL`, `SPREADSHEET_ID`, `GOOGLE_SERVICE_ACCOUNT_JSON`. Для docker-compose дополнительно `POSTGRES_PASSWORD` и `DOMAIN`, для локальной разработки необязательный `DATA_DIR` меняет папку с настройками таблицы.

Без `ADMIN_PASSWORD` вход в админку невозможен. Без `SESSION_SECRET` сервер возьмет случайный секрет и напишет об этом в лог. Сессии админа хранятся в памяти процесса, поэтому после каждого перезапуска надо войти заново.

## Запуск локально

```
cp .env.example .env
npm install
docker run -d --name guitarnik-pg -e POSTGRES_USER=guitarnik -e POSTGRES_PASSWORD=devpass -e POSTGRES_DB=guitarnik -p 55432:5432 postgres:17-alpine
DATABASE_URL=postgres://guitarnik:devpass@127.0.0.1:55432/guitarnik ADMIN_PASSWORD=test npm start
```

Сайт поднимается на `http://localhost:3000` или на порту из `PORT`.

## Тесты

```
DATABASE_URL=postgres://guitarnik:devpass@127.0.0.1:55432/guitarnik npm test
DATABASE_URL=postgres://guitarnik:devpass@127.0.0.1:55432/guitarnik npm run test:mutation
```

Первая команда прогоняет проверки чистых функций и сценарии через HTTP: путь гостя от участника до взятой хотелки, независимость голосов, валидацию форм, экранирование ввода, админку, лайнап, вкладки и поиск. Каждый сценарий сам создает нужное состояние в чистой базе, поэтому пропусков и ложных зеленых нет.

Вторая команда портит код в семнадцати местах и проверяет, что тесты это замечают. Если какая-то мутация выживает, значит проверка дырявая.

## Голоса

С одного устройства за песню можно проголосовать один раз, повторный клик снимает голос. Сайт ставит долгую куку с случайным идентификатором и держит отметки о голосах в отдельной таблице. Защита рассчитана на честных людей: очистка кук или другой браузер обходят ее, и это осознанно.

## Лайнап

Порядок вечера собирается в админке на вкладке «Лайнап»: можно добавить любую заявленную песню, вставить перерыв, двигать элементы вверх и вниз, собрать весь список одной кнопкой по числу лайков. Пока лайнап не опубликован, посетители на странице «Лайнап» видят сообщение, что он готовится. Публикация и скрытие переключаются одной кнопкой.

## Деплой

Код на сервере лежит в клоне этого репозитория:

```
cd ~/guitarnik
./deploy.sh
```

Скрипт забирает `main` из GitHub, пересобирает образ, перезапускает контейнеры и показывает статус. Локальные правки на сервере он затирает. Файл `.env`, папка `data` с настройками таблицы, том Postgres и данные databasus в репозиторий не входят и переживают любой деплой.

Логи: `docker compose logs -f app`. Сервер ходит в GitHub по ключу `~/.ssh/id_ed25519_guitarnik`, публичная часть добавлена в репозиторий как deploy key на чтение.

## Админка

`/admin` закрыта паролем из `ADMIN_PASSWORD`. Внутри пять вкладок: сводка, лайнап, участники, песни, лайки.

Статус песни меняется прямо в строке. Кнопка «Править» открывает полную карточку песни или участника со всеми полями. Кнопка «Удалить» спрашивает подтверждение и удаляет насовсем: песня уходит вместе со своими лайками, голосами и местом в лайнапе, участник уходит, а его имя исчезает из составов, но сами песни остаются. Если песню надо просто убрать с глаз, не теряя, поставь ей статус «отменена»: такие песни видны только в админке.

Выгрузка `/admin/export/setlist.json` отдает песни со статусами «заявлена» и «в сетлисте» в формате `id`, `artist`, `title`, `sing`, `lyrics` - это вход для суфлера.
