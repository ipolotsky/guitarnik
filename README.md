# Гитарник

Сайт для сбора песен на вечер живой музыки. Гости без регистрации смотрят список, лайкают, добавляют свои песни и заказывают чужие. Организаторы заходят в админку по паролю.

Стек: Node.js, Express, EJS, Bootstrap 5.3 с CDN, sqlite через встроенный модуль Node, Google Sheets через сервис-аккаунт.

## Где лежат данные

Основное хранилище - файл `data/guitarnik.sqlite` на сервере. Сайт работает на нем и без всякой Google-таблицы: открыл, добавил песню, все сохранилось.

Google-таблица подключается отдельно и работает как зеркало. Когда она подключена, каждая новая или измененная строка уходит в нее в фоне, а если таблица недоступна, запись ждет в очереди и уедет позже. В админке на сводке есть две кнопки: «Выгрузить все в таблицу» переписывает листы содержимым базы, «Загрузить из таблицы» затягивает строки обратно в базу по id. Загрузка ничего не удаляет: строка, стертая в таблице руками, останется в базе, пока ее не отменят через админку.

Так что порядок такой: сначала сайт просто работает, таблицу можно подключить когда угодно, а можно и не подключать.

## Настройка Google

1. Создать проект в Google Cloud Console.
2. Включить в нем Google Sheets API.
3. Создать сервис-аккаунт и ключ к нему в формате JSON, скачать файл ключа.
4. Создать Google-таблицу и расшарить ее на email сервис-аккаунта с правом редактирования. Email виден в поле `client_email` в файле ключа.
5. Скопировать `SPREADSHEET_ID` из адреса таблицы: это длинный кусок между `/d/` и `/edit`.
6. Превратить ключ в одну строку base64:

```
base64 -i key.json | tr -d '\n'
```

Полученную строку положить в `GOOGLE_SERVICE_ACCOUNT_JSON`. Файл ключа в репозиторий не класть.

## Запуск локально

```
cp .env.example .env
npm install
npm start
```

Переменные в `.env`: `PORT`, `ADMIN_PASSWORD`, `SESSION_SECRET`, `SPREADSHEET_ID`, `GOOGLE_SERVICE_ACCOUNT_JSON`. Без `ADMIN_PASSWORD` вход в админку невозможен. Без `SESSION_SECRET` сервер возьмет случайный секрет и напишет об этом в лог, сессии админа сбросятся при перезапуске.

Сайт поднимается на `http://localhost:3000` или на порту из `PORT`.

## Подключение таблицы

Зайти в `/admin/login`, ввести пароль, открыть `/admin/settings`, проверить `SPREADSHEET_ID` и названия листов, нажать «Создать структуру». Недостающие листы создадутся, в первую строку каждого запишутся заголовки. Кнопка «Проверить связь» показывает, какие листы найдены, на месте ли заголовки и сколько в них строк данных.

Дальше на сводке админки нажать «Выгрузить все в таблицу»: то, что уже накопилось в базе, уедет в листы. После этого синхронизация идет сама.

## Голоса

С одного устройства за песню можно проголосовать один раз. Сайт ставит долгую куку с случайным идентификатором и держит отметки о голосах в отдельной таблице базы, в лист «Лайки» они не попадают. Проголосовавший видит кнопку закрашенной и неактивной. Защита рассчитана на честных людей: очистка кук или другой браузер обходят ее, и это осознанно.

## Бекапы

Каждую ночь после четырех утра сервер делает копию базы в `data/backups/guitarnik-ГГГГ-ММ-ДД.sqlite` и держит последние тридцать файлов. В сводке админки видно дату последнего бекапа и есть кнопка «Сделать бекап сейчас». Выгрузка `/admin/export/data.json` отдает все три таблицы одним файлом.

Восстановление: остановить контейнер, положить нужный файл из `data/backups` на место `data/guitarnik.sqlite`, запустить обратно.

Нужен Node 22.13 или новее: база работает на встроенном модуле `node:sqlite`.

## Деплой на сервер с docker

Рядом лежат `Dockerfile` и `docker-compose.yml` под сервер с общим Traefik: сеть `web`, роутер на домен из переменной `DOMAIN`, сертификат от резолвера `letsencrypt`. Папка `data` примонтирована с хоста, поэтому `config.json` и `backup.sqlite` переживают пересборку.

```
cd ~/guitarnik
docker compose up -d --build
docker compose logs -f app
```

После правки кода на сервере та же команда `docker compose up -d --build` пересобирает образ и перезапускает контейнер. Переменные окружения лежат в `~/guitarnik/.env` рядом с compose, там же `DOMAIN`.

Процесс в контейнере работает от пользователя `node` с uid 1000, поэтому папке `data` на хосте нужен этот владелец: `sudo chown -R 1000:1000 data`. Иначе бекапы и сохранение настроек не смогут писать на диск.

Для Railway и Render подходит обычный `npm start` с портом из `PORT`, но диск там не сохраняется между деплоями: `data/config.json` и бекапы пропадут, постоянные значения держать в переменных окружения.

## Админка

`/admin` закрыта паролем из `ADMIN_PASSWORD`. Внутри четыре вкладки: сводка, участники, песни, лайки. У песни меняется статус прямо в строке, кнопка «Удалить» ставит статус «отменена» и строку в таблице не трет. Выгрузка `/admin/export/setlist.json` отдает песни со статусами «заявлена» и «в сетлисте» в формате `id`, `artist`, `title`, `sing`, `lyrics` - это вход для суфлера.
